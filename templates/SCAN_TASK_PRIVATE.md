## 最重要的一條規則

**你不需要、也不可以把逐字稿抄回來。**

清稿由程式執行：你只要指出「哪個字串要換成哪個字串」，Python 會用
`re.sub` 套用到全文。你回傳的內容應該是幾百個字，不是幾千個字。

下面每一段發言都有一個編號（`#12`）。要指出某句話時，**回傳那個編號**，
不要複述那句話的內容。

## 你要做三件事

### 1. `replacements` — ASR 錯字對照

依上下文判斷聽錯的字，列出「原文 → 正確」。

- `find` 必須是逐字稿裡**真的出現過的字串**，一字不差（含全形標點）。
  程式會逐一比對，找不到的會被丟掉。
- 只放你**有把握**的：同音字、專有名詞、人名公司名（例：`播空→撥空`、
  `全线→權限`、`誓約→續約`）。
- `find` 要夠長到不會誤傷別的句子。單一個字通常太短。
- 不要放整段話，不要用它來潤飾語氣或改寫語意。
- 沒有要改的就回空陣列。

### 2. `speakers` — 講者標籤是誰

`label` 照逐字稿原樣寫（`講者3` 就寫 `講者3`）。`guess` 是你判斷的真實姓名。
`confidence` 只能是 `high` 或 `low`。`why` 寫你的判斷依據（你自己的話，不要抄原文）。

### 3. `questions` — 只有使用者能回答的問題

挑出**答錯會讓整份文件出錯**的地方。寧可少，不要湊數：本段最多 {{MAX_PER_CHUNK}} 題。
以下**不要**問：

- 你自己讀上下文就能判斷的錯字（那個放進 `replacements`，不要問）。
- 對文件結論沒有影響的細節（誰先講、語助詞、閒聊）。
- 需要使用者打字寫長篇的問題。**每題都要能用點選回答。**

每題的 `type` 五選一：

| type | 用在什麼情況 |
|---|---|
| `speaker` | 這個講者標籤到底是誰（最重要，優先問） |
| `term` | 專有名詞／人名／公司名 ASR 聽成好幾種寫法，要定於一 |
| `unclear` | 音檔不清楚，關鍵資訊聽不出來（金額、日期、數量） |
| `conflict` | 前後說法互相矛盾，需要使用者裁決哪個算數 |
| `undecided` | 會中沒講清楚結論，但文件必須寫（例：這件事到底決議了沒） |

`options` 是給使用者點的按鈕：2–5 個具體選項。`best_guess` 必須是 `options` 其中之一。
`key` 是這題針對的對象（講者標籤或詞），用來跨段合併同一題。
`evidence_turns` 填**發言編號**（例：`[12, 15]`），程式會自己去把那幾段原文貼上來。
