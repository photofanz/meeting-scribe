## 你要做兩件事

### 1. 清稿草稿（draft）

把**本段**的逐字稿修成可讀的草稿：

- 繁體中文（台灣用語），不得殘留簡體字。
- 依上下文修 ASR 錯字與同音字（例：`播空→撥空`、`全线→權限`、`誓約→續約`）。
- **保留每一段發言、保留 `[HH:MM:SS]` 時間戳、保留講者標籤原樣**（`講者3` 就寫 `講者3`，
  這一階段**還不要**改成真實姓名——姓名要等使用者回答完才統一換）。
- 不刪內容、不摘要、不潤飾語氣、不改寫語意。聽不出來的地方寫 `（音檔不清楚）`。
- 輸出格式與輸入相同：

  ```
  **── 講者3 ──**　`[00:12:01 – 00:12:48]`

  發言內容……
  ```

### 2. 問題卡（questions）

挑出**只有使用者能回答**、而且**答錯會讓整份文件出錯**的地方。
寧可少，不要湊數：本段最多 {{MAX_PER_CHUNK}} 題。以下**不要**問：

- 你自己讀上下文就能判斷的錯字（那個直接放進 `replacements`，不要問）。
- 對文件結論沒有影響的細節（誰先講、語助詞、閒聊）。
- 需要使用者打字寫長篇的問題。**每題都要能用點選回答。**

每題的 `type` 六選一：

| type | 用在什麼情況 |
|---|---|
| `speaker` | 這個講者標籤到底是誰（最重要，優先問） |
| `term` | 專有名詞／人名／公司名 ASR 聽成好幾種寫法，要定於一 |
| `unclear` | 音檔不清楚，關鍵資訊聽不出來（金額、日期、數量） |
| `conflict` | 前後說法互相矛盾，需要使用者裁決哪個算數 |
| `undecided` | 會中沒講清楚結論，但文件必須寫（例：這件事到底決議了沒） |

`options` 是給使用者點的按鈕：2–5 個具體選項，用逐字稿裡真的出現過的寫法，
最後一個可以是「以上皆非／我來補充」。`best_guess` 必須是 `options` 其中之一。

## 輸出

**只寫一個檔案**：`{{OUT_PATH}}`，內容是 JSON：

```json
{
  "draft": "本段清稿後的完整 markdown（字串，含換行）",
  "replacements": [
    {"find": "播空", "replace": "撥空", "note": "同音字"}
  ],
  "speakers": [
    {"label": "講者3", "guess": "王總", "confidence": "high",
     "why": "自稱我們公司這邊、被稱王總"}
  ],
  "questions": [
    {"type": "speaker", "key": "講者3",
     "question": "「講者3」是誰？",
     "options": ["王總", "李經理", "以上皆非／我來補充"],
     "best_guess": "王總",
     "evidence": [{"timestamp": "00:12:01", "text": "逐字稿原文片段"}]}
  ]
}
```

`replacements` 只放你**有把握**的修正（已經套進 draft 了，這裡是留給使用者回查的對照表）。
`confidence` 只能是 `high` 或 `low`。`key` 是這題針對的對象（講者標籤或詞），用來跨段合併同一題。
